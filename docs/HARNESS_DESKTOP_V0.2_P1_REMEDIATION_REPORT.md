### R1 — Local calendar "Today"

R1_LOCAL_TODAY_STATUS=PASS
ROOT_CAUSE=The previous `is_today_ms` bucketed by `seconds.div_euclid(86_400)` on the Unix
epoch (UTC days), so "today" flipped at UTC midnight — 08:00 local for UTC+8 users — instead
of local midnight.
FIX=Added `chrono` (clock+std) and rewrote `is_today_ms` to compare **local calendar dates**
via `chrono::Local` (DST-aware, resolves the correct offset per timestamp). Added a
deterministic fixed-offset seam `same_local_day(ts, now, offset)` (`#[cfg(test)]`) so boundary
tests do not depend on the developer machine's timezone.
SELF_REVIEW_ROUNDS=2
FOCUSED_TESTS=7 boundary tests: same civil day (UTC), previous local day, 23:59:59→00:00:00
boundary, UTC+8 day flip, negative offset day flip, "now is today", platform-timezone date.
ADVERSARIAL_TESTS=UTC+8 and UTC-5 midnights asserted to split correctly (15:59 vs 16:00 UTC for
+8; 04:59 vs 05:00 UTC for -5).

Note on DST: production `is_today_ms` is DST-aware via `chrono::Local` (OS timezone DB); the
deterministic tests exercise fixed-offset cases only (no bundled-tz DST test was added — not
fabricated).

### R2 — Production-default runtime integrity

R2_RUNTIME_INTEGRITY_STATUS=PASS
ROOT_CAUSE=`verify_checksums` ran only when `HD_VERIFY_RUNTIME=1`, and it ran *after* the node
version probe (i.e. after bundled code executed). Also the shipped `manifest.json` used
snake_case checksum keys while the Rust struct expected camelCase, so checksums were silently
read as empty.
FIX=Integrity verification is now unconditional and runs **before** `probe_node_version`.
Introduced `runtime::ResolveError` (Integrity vs Other); an `Integrity` error never falls back
to the system runtime (even with `HD_SYSTEM_RUNTIME=1`). `HD_VERIFY_RUNTIME` was removed.
Fixed the manifest key casing (now `nodeSha256`/`harnessEntrySha256`), regenerated by the R3
materializer.
PRODUCTION_DEFAULT_VERIFICATION=true
INTEGRITY_COVERAGE=Node binary (SHA-256) + Harness `@deepseek-ai/dsh/lib/bin.js` entry
(SHA-256). It does **not** hash the entire 343 MB dependency closure.
STARTUP_IMPACT=One SHA-256 over the ~112 MB node binary + one over the ~8 KB entry per startup
(≈ 0.2–0.3 s estimated); not benchmarked precisely. No full-tree hashing.
ADVERSARIAL_TESTS=tampered `bin.js` (appended a byte) → startup failed closed with "bundled
Harness entry integrity check failed …"; restored → startup reached READY again. Missing
checksums → fails closed (unit test). Integrity mismatch is distinguished from version mismatch
(unit test).

### R5 — Windows signal source blocker

SIGNAL_HOOK_BLOCKER=REMOVED (the `signal_hook::iterator::Signals` usage is now inside
`#[cfg(unix)]`; Windows relies on Tauri's `RunEvent::Exit`/`ExitRequested`).

Details: after the cfg fix, `cargo check --target x86_64-pc-windows-msvc` no longer stops on the
signal source; it stops at toolchain-only failures — `zstd-sys` requires a Windows C
cross-compiler (`cc --target=x86_64-pc-windows-msvc`) and `tauri-winres` requires `llvm-rc`, both
absent on this macOS host. `WINDOWS_SOURCE_BLOCKER_SIGNAL_HOOK=FIXED` is claimed only at the
source level (verified by inspection: the sole `signal_hook::iterator` use is `#[cfg(unix)]`);
full Windows type-checking is NOT proven past the toolchain.
